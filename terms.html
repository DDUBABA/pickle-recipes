1. 서비스와 이용 동의

Pickle Recipes(피클 레시피)는 피클 제작사와 무관하게 운영되는 비공식 서드파티 커뮤니티입니다. 제작사의 공식 서비스·제휴 서비스가 아니며, 게시물에 대한 제작사의 검토·보증을 의미하지 않습니다. 운영자는 DDUBABA입니다. 이 약관은 본 커뮤니티의 자료 검색·배포·기여 접수에만 적용되며, 피클 제작사의 약관이 아닙니다. 피클이라는 이름은 자료의 활용 대상을 설명하기 위해 사용합니다. 사용자의 AI, 외부 서비스, 로그인 브릿지는 각각 별도의 시스템입니다.

이 사이트의 다운로드·설치·실행·업로드 연동을 이용하려면 이용약관, 면책, MIT 라이선스 및 아래 기록 수집에 명시적으로 동의해야 합니다. 피클은 사용자에게 전문 링크가 포함된 버튼 카드를 제시해야 하며 동의를 대신 선택할 수 없습니다. 동의하지 않으면 다운로드·제출 등 실행성 기능을 이용할 수 없습니다. 웹 첫 화면, 카탈로그, 키워드 검색, 상세 README·버전·릴리즈 노트·다운로드 수와 공개 안내 문서는 동의 없이 자유롭게 열람할 수 있습니다. 웹에서는 실제 다운로드를 요청할 때 동의를 확인하고 동의 후 요청한 다운로드를 진행합니다.

다운로드·제출 등 실행성 기능 이용 시 최신 약관 버전을 확인합니다. 버전이 변경되면 즉시 중단하고 새 버튼 카드로 재동의를 받아 서버에 기록한 뒤 진행합니다. 동의 토큰은 사용자 측에 안전하게 보관하며 공개하지 않습니다. 동의와 접근 토큰은 고정 만료일 없이 약관 변경 또는 연결 해제(철회) 전까지 유효합니다. 유효한 동의 확인·다운로드·제출 요청은 최근 활동 시각을 갱신하며, 아래 180일 미사용 데이터 삭제 정책은 별도로 적용됩니다.

2. 자동화와 면책

공유 코드는 현재 상태로 제공됩니다. 정확성·지속적 동작·목적 적합성이나 외부 서비스와의 호환성을 보장하지 않습니다. 외부 API 변경, 서비스 중단, AI 판단 오류, 사용자 설정에 따라 잘못된 실행이 발생할 수 있습니다.

사용자는 실행 전 대상·권한·비용·영향을 확인하고, 결제·삭제·전송 등 중요한 동작에는 별도의 실행 승인을 적용해야 합니다. 레시피·커넥터 실행 후 예약·결제·삭제·취소 등 실제 처리 결과를 최종 확인하고 이용 결과에 대한 책임을 지는 주체는 사용자 본인입니다. AI의 완료 안내만으로 처리가 끝났다고 판단하지 말고 대상 서비스의 실제 결과를 확인해야 합니다.

운영자는 자동화 실행 결과로 발생한 직접·간접 손해에 대해 책임을 지지 않습니다. 다만 법률상 배제할 수 없는 책임은 제외합니다.

제3자 서비스의 약관과 접근 정책을 준수하고 권한이 없는 시스템에 접근하지 않아야 합니다. 보안 스캔은 위험을 줄이지만 안전성을 보증하지 않으며, 접수 PR은 운영자 검토 후 병합합니다.

3. MIT 공개 라이선스와 기여

공유 코드와 문서는 MIT 라이선스 전문에 따라 공개됩니다. 저작권 및 허가 고지를 유지해야 합니다. 업로더는 해당 자료를 공개할 권한이 있어야 하며 제3자의 비밀·권리·개인정보를 포함해서는 안 됩니다.

‘동의하고 이용’을 선택하면 자동 업로드 허용도 이용 동의에 기본 포함됩니다. 이 사이트의 제출 규격과 개인정보·민감정보 제거 검증을 마친 공통 코드만 공개 제출할 수 있습니다. 개인 프로필, 인증 정보와 사용자 개인 설정은 제출하지 않습니다. 자동 업로드를 원치 않으면 AI에게 자동 업로드 중지를 요청하거나 이용 동의를 철회할 수 있습니다. AI는 중지 요청을 보존하고 사용자가 재개를 요청하기 전까지 자동 업로드하지 않아야 합니다. 다시 동의하더라도 기존 중지 요청을 임의로 해제해서는 안 됩니다.

PR 번호가 접수번호이며 병합은 보장되지 않습니다. 버전과 릴리즈 이력은 서버 자동화가 확정합니다. 요청자의 공개 별칭, 기준 버전, 동의 ID, 약관 버전, 요약 및 코드가 GitHub 공개 PR에 기록됩니다. 비밀 동의 토큰, 개인 식별자 원문, IP 주소와 사용자 에이전트는 PR에 게시하지 않습니다. 공개 기여는 복제·포크될 수 있어 완전한 회수가 불가능할 수 있습니다.

4. 동의·다운로드 기록 수집

필수 수집 항목은 사용자 식별자(피클 핸들 또는 임의 식별자), 접속 IP, User-Agent, 클라이언트 종류, 동의 시각·최근 활동 시각·철회 시각·약관 버전·동의 ID, 다운로드 항목·종류·버전·시각입니다. 표시 이름은 선택입니다. 실명·전화번호·이메일 대신 임의 식별자를 사용하세요.

목적은 약관 동의 증빙, 다운로드 집계, 서비스 운영 및 오남용 확인입니다. 기록은 Cloudflare D1에 보관하고 관리자만 사용자별 통계를 조회합니다. 항목별 다운로드 횟수는 서비스에 표시됩니다. 계정 비밀번호, 서비스 인증키, 개인 프로필 파일은 이 사이트에 보내지 않습니다.

동의는 약관 변경 또는 연결 해제(철회) 전까지 유효하며 고정 만료일은 없습니다. 다만 개인정보 보관을 최소화하기 위해 철회 후 180일이 지난 동의와 최근 활동(last_used_at) 기준 180일 이상 미사용한 미철회 동의는 식별자·토큰 해시·관련 동의 이력 및 다운로드 상세 기록과 함께 삭제합니다. 최근 활동한 미철회 동의는 유지합니다. 동의 기록의 IP·User-Agent와 개별 다운로드 상세 기록은 각 기록 시점부터 180일이 지나면 삭제하고, 항목별 누적 다운로드 수는 유지합니다. 서버의 일일 정리 또는 쓰기 요청 시 정리로 처리하며 정리 간격은 최소 24시간입니다. 삭제된 동의로 다시 다운로드·제출하려면 새 동의가 필요합니다. 백업의 이전 사본은 D1 복구 보관 기간 내에 남을 수 있으며 공개 PR 이력은 GitHub에 남습니다. 유효한 열람·정정·삭제 요청은 운영자가 별도로 검토합니다. Cloudflare 및 GitHub의 인프라 처리 위치와 정책이 적용될 수 있습니다.

동의를 거부해도 공개 자료를 둘러볼 수 있으나 다운로드·제출 등 실행성 기능에는 동의가 필요합니다. 브라우저의 ‘이용 동의 철회’ 또는 인증된 POST /api/consent/revoke 요청은 서버에 철회를 기록하고 해당 토큰의 연동을 차단합니다. 피클에게 레시피 사이트 연결 해제 또는 관련 기능 제거를 요청하는 경우에도 같은 철회 API를 호출해야 합니다. 동의·철회 증빙은 철회 후 180일이 지나면 삭제하며 즉시 기록 삭제 요청과는 구분됩니다. 기록 열람·삭제·정정 요청은 운영 저장소 문의로 비공개 연락 경로를 요청하세요. 공개 이슈에는 개인 식별자나 동의 토큰을 작성하지 마세요.

5. 사용자 설정 보존

공유 파일에는 공통 코드만 포함합니다. 연동 도구는 이 커뮤니티의 저장 규칙에 따라 비비밀 개인정보를 사용자 측 ~/.config/pickle-profile/profile.json에서 우선 참조해야 합니다. 인증 정보는 사용 환경에서 지원하는 보안 보관소 또는 로그인 브릿지로 관리해야 합니다. 업데이트 시 개인 설정과 예약 폴더를 보존해야 합니다. 이 경로와 연동 규칙은 이 사이트가 정한 것이며 제작사의 공식 저장 규격을 뜻하지 않습니다.

6. 공식 문의·건의 창구

이 커뮤니티의 공식 문의 창구는 문의·건의하기입니다. 피클 제작사의 고객지원 창구가 아닙니다. GitHub 계정이 없으면 웹 문의 폼 또는 POST /api/feedback으로 의견을 보낼 수 있습니다. 문의에는 다운로드·공유 동의나 동의 토큰이 필요하지 않습니다.

웹 폼·API 문의의 분류, 제목, 내용, 선택한 임의 별칭, 접수번호 및 접수 시각을 문의 처리와 서비스 개선 목적으로 Cloudflare D1에 저장합니다. 운영자만 조회하며 자동으로 GitHub에 게시하지 않습니다. 접수 시점부터 180일이 지나면 일일 정리 또는 쓰기 요청 후 정리로 삭제합니다. 정리 간격은 최소 24시간이며 백업에는 D1 복구 보관 기간 동안 남을 수 있습니다. 문의 행에는 IP·User-Agent·동의 토큰을 저장하지 않습니다. 오남용 방지를 위한 한시적 요청 제한 키에는 일별 HMAC으로 변환한 접속 주소를 사용하며 만료 후 정리합니다. Cloudflare 인프라 처리에는 해당 서비스 정책이 적용됩니다.

이메일·전화번호·주소·개인 경로·비밀번호·인증 토큰을 작성하지 마세요. 알려진 개인정보·토큰 패턴은 차단하지만 모든 민감정보를 탐지할 수는 없습니다. 이 양식은 비밀 자료 전달 경로가 아닙니다. GitHub 이슈는 공개되므로 같은 주의가 필요합니다. 접수번호를 보관해 주세요. 개별 답변·처리·채택을 보장하지 않으며, 수정·삭제 요청은 접수번호만 기재하여 같은 창구로 요청할 수 있습니다. 접수번호 자체는 본인 확인 수단이 아니며 운영자가 요청의 정당성을 별도로 검토합니다.
